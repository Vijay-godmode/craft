CAREERCRAFT QA PLAYGROUND — MASTER IMPLEMENTATION PLAN
=========================================================

TARGET APPLICATION
------------------
Existing application:
https://careercraft-lt99.onrender.com/

Goal:
Transform CareerCraft into a production-like, full-stack QA/SDET testing
playground where a tester can practice UI, API, database, integration,
functional, accessibility, visual, security, performance, load, stress,
spike, soak, resilience, concurrency, observability and CI/CD testing.

IMPORTANT:
- First inspect the existing application and codebase.
- Do NOT rewrite the application blindly.
- Preserve all existing functionality.
- Reuse the existing stack where practical.
- Implement this plan incrementally.
- After every phase, run relevant tests and verify the application.
- Keep intentionally broken/vulnerable/fault-injection functionality isolated
  from the normal application and disabled in production.
- Never commit secrets or expose database credentials to the frontend.
- Never run destructive stress/load tests against production.


=========================================================
PHASE 0 — DISCOVERY AND BASELINE
=========================================================

2. Identify:
   - frontend framework

   - current test framework
   - existing pages/components

5. Identify current defects and technical limitations.
6. Create:
   - QA_LAB_IMPLEMENTATION_PLAN.md
   - ARCHITECTURE.md

Do not make major architectural changes until this discovery is complete.

=========================================================
ENGINEERING RULES
=========================================================

1. Inspect before modifying.
2. Preserve existing functionality.
3. Implement incrementally.
4. Keep application code and test infrastructure separated.
5. Use environment variables.
6. Never commit secrets.
7. Never expose DB credentials to frontend.
8. Use deterministic test data.
9. Give every test scenario a clear expected result.
10. Use stable selectors where appropriate.
11. Keep failure injection disabled by default.
12. Keep security training scenarios isolated.
13. Keep heavy performance tests controlled.
14. Never target production with destructive tests.
15. Avoid unnecessary dependencies.
16. Prefer maintainable architecture over clever code.
17. Add tests for every new feature.
18. Run relevant tests after every phase.
19. Fix regressions before continuing.
20. Do not claim a phase is complete until it has been verified.


=========================================================
IMPLEMENTATION WORKFLOW FOR COPILOT
=========================================================

For EACH phase:

1. Explain what currently exists.
2. Identify files that will change.
3. Propose the smallest safe implementation.
4. Implement the phase.
5. Run lint/build/tests.
6. Fix failures.
7. Verify manually where required.
8. Update documentation.
9. Report:
   - changed files
   - new functionality
   - tests executed
   - test results
   - known limitations
10. Wait before starting the next major phase if the implementation
    introduces architectural uncertainty.

Do NOT attempt to implement all phases in one operation.

Start with PHASE 0.

After PHASE 0 is complete and verified, proceed sequentially through
PHASE 1 onward.
